门店通设计规范

门店通是给汽车经销商用的新媒体营销后台。总部和大区在电脑前横向比几十家门店，店长、新媒体专员和销售顾问在展厅里拿手机跟进线索。这份手册写给做页面的人：照着它，不看旧页面也能做出一致的新页面。

新增或修改组件的流程

规则：页面里不临时造组件，先进库再用。库里没有或不合适，就走下面 6 步。第 6 步全部对上，变更才算结束。

  1. 提需求产品、前端开发、测试，任何人

    发现库里没有或不合适，提给 UI 设计。写清三件事：哪个页面，什么场景，现在的截图。

  2. 改库UI 设计

    先改组件库和 tokens，不先改页面。写更新记录：改了什么、为什么、影响哪些组件。

  3. 升版本号UI 设计

    大改升主版本（v1.0 → v2.0，如换主色、改字阶）；新增组件或 token 升次版本（v1.0 → v1.1）；微调升修订号（v1.1.0 → v1.1.1，如改一个状态的颜色）。

  4. 同步UI 设计

    按组件使用清单列出受影响的页面，把 tokens 文件和变更清单同步给前端开发和测试。

  5. 实现前端开发

    引用新的 tokens 和组件类实现，不复制样式，不写行内样式。

  6. 走查UI 设计，测试一起验收

    逐页走查受影响页面，全部和库对上，变更结束。对不上的回到第 5 步。

变更类型例子版本号要不要走查全部页面
大改换主色、改字阶、删组件主版本 +1要
新增新组件、新 token、组件新状态次版本 +1只走查用到的页面
微调改一个状态的颜色、修尺寸偏差修订号 +1只走查用到的页面
