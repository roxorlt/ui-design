门店通设计规范 v0.1 初稿

给 roxor 讨论用，2026-10-20。只是设计稿，没有改 demo 代码，也没有部署。主线是屏效：同样的屏幕放下更多有用的信息，把面积留给「谁掉队」「谁要回电」这类要动手的事。

依据

  • 需求：projects/dealer-saas/PRD.md（v0.1 + v1.1 补充），qa-pm/PRD-v1.2-闭环补充.md（评审稿），decisions.md（主色黑色、虚构品牌星驰汽车、演示数据口径），qa-pm/闭环缺口清单-v1.md，research/store-benchmarks-20261014.md。
  • 行业和用户：汽车经销商新媒体矩阵营销。买单方是品牌总部和经销商集团（电脑前横向比 48 家门店）；使用方是店长、新媒体专员、销售顾问（展厅里用手机，线索要 30 分钟内跟进）。
  • 看过的页面：线上 demo（roxorlt.github.io/mdt-demo）登录、总部 / 大区 / 门店驾驶舱、门店矩阵和门店详情、线索列表和详情抽屉、AI 创作（含生成后）、直播间列表和详情、直播 PK、任务中心（总部 / 门店）、内容分发、手机工作台、角色与权限、销售顾问线索页，共 18 个页面状态，PC 1440×900 和手机 390×844 各一套，存在 shots/pc 和 shots/m。四个角色的首页（总部、大区、店长驾驶舱，销售顾问线索页）都在下面审计里。

关键设计决定

  • 仪表盘法则：一屏一块主表从汽车仪表盘借来的：车速表最大，油量水温很小。每页最多一个 32px 大数字，其余写成 20px 指标条。驾驶舱指标区从 264px 降到 88px，首屏掉队门店从 1 行变成 14 行。
  • 指标兼作筛选线索、发布记录、任务这类页面，「待跟进 158」「失败 1」直接做成筛选芯片，点了就筛。一排大卡省掉，手机线索首屏从 0 条变成 7 条。
  • 沿用黑色和琥珀，收窄用途遵守「主色黑色」，琥珀保留（视频里已出现）。改的是用法：琥珀只表示「需要你处理」，图表主线改白色；去掉青色，换成只管「进行中 / 链接 / 焦点」的信息蓝。面板靠三档灰分层，不加阴影。
  • 手机换写法，不是堆窄侧栏改底部标签栏，顶栏 48px；表格改成三行列表（主语、AI 摘出的原话、来源归属）；角色切换和重置演示数据收进「我的」。手机不再横滑表格。
  • 演示标注只说一次「演示数据」从每张卡上的「示意」徽标（店长首屏 12 处）收成顶栏一处，满足 PRD「角落标注」的要求，又不干扰工作界面。

需要 PM 确认的问题

  1. 按钮叫「提醒店总」还是「提醒店长」？角色叫「门店店长」，消息写「店长」，按钮写「店总」。规范建议统一成「店长」，但 PRD v1.2 验收文案写的是「提醒店总」。
  2. 「去完成」要不要写成去处？建议「去发视频」「去开直播」「去回私信」，用户点前就知道会去哪。PRD 1.5 写的是「去完成」。
  3. 手机端要不要浅色「展厅白」？展厅强光下黑底容易反光。PRD 定了黑色后台，浅色只作为手机工作台和销售端的备选，token 已备好。
  4. 手机端范围：PRD 写「电脑端为主，手机工作台单独一页」，但店长和销售顾问的真实使用在手机。手机是只做工作台一页，还是所有页面都要能用？这决定底部标签栏放哪几项。
  5. 门店驾驶舱里的「加入门店通前 → 现在」：是给客户看的销售话术，放在店长日常首页合适吗？建议移到演示专用位置。
  6. 缺的状态：PRD 没写这些页面的空、加载、错误状态：消息中心空列表、发布记录筛选无结果、脚本库无下发、转交时店里没有其他在岗顾问、新建任务提交失败。规范给了写法，文案需确认。
  7. 发布状态够不够：PRD 只有待发布 / 已发布 / 失败。真实平台会有「发布中」「审核中」「已取消」，demo 时钟不走可以不做，正式产品要补。
  8. 销售顾问的「导出」：PRD v1.2 规定销售顾问没有「导出」，线上 demo 仍显示，看起来是 v1.2 还没开发。
  9. PRD v1.3 今天会出：本稿按 v1.2 评审稿覆盖组件；v1.3 有新增组件时需要补。
